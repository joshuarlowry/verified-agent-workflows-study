# Context setup procedure

The approved server, version, tools and exclusions are defined solely in [registration.json](registration.json), `mcp_setup` and `documentation_corpus`. Use one common OpenCode adapter. Shell/search provide navigation; public Playwright commands provide UI feedback. Other installed MCP servers and local RAG are excluded from this cohort and introduce no qualification gates.

1. **Approve content first.** A named independent reviewer outside the subject families approves the curator's source inventory, omitted topics, version coverage, extraction and absence of task-specific answers. The GPT-family coordinator may propose sources and mechanically package approved inputs but cannot approve its own corpus. Record identity, source hashes and signoff before calibration.
2. **Build only approved docs.** Derive the corpus from the canonical candidate stack and qualified lockfile. Prefer official tagged/package-local docs; record dated release-family coverage honestly. Resolve actual Context library IDs or build source packages. Provide the identical read-only source-file copy to every agent. No solutions, sealed checks, other repositories or run logs enter the corpus.
3. **Isolate Context.** The observed implementation stores packages under the OS home directory. Use a dedicated identity/container with approved packages mounted there; do not inherit the host's global catalog or credentials or assume an unsupported directory override. Keep writable process state independent. Prefetch approved archives and serve an exact-version `--libs` allowlist with live registry/download access blocked.
4. **Qualify once, check roles.** Verify initialize, catalog, a real documented API lookup, source/version attribution, no-result behavior, wrong-version/unlisted-library rejection, forbidden-path/network rejection and bounded timeout/crash behavior. Then smoke direct, supervisor and broker-launched worker permissions/config inheritance on that same adapter. A successful local Next documentation lookup is historical transport evidence, not qualification of the new corpus.
5. **Freeze.** Publish sanitized launch/tool manifests, corpus/source/archive hashes, exact queries and evidence, independent content signoff, role inheritance and coverage gaps. Keep raw content-bearing logs private. Prestart/health-check before timing; retrieval during a run counts toward its deadline. Record preparation and retrieval latency separately. No embedding/generative retrieval service or hidden extra model is part of this bundle.

Every required topic needs relevant attributed content within its declared version coverage. Isolation tests inspect effective filesystem/network/tool access, not just polite refusals. Any missing required source or adapter behavior blocks calibration. Fixes use a new manifest and requalification before dispatch, with original evidence retained.
