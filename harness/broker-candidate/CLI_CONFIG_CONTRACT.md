# Candidate contract — synthetic only, not authorized for dispatch

`broker.py` is a library embedded in a trusted per-parent controller, not a standalone service. The only tested runnable worker is `tests/fake_worker.py`. Production/registered mode is **unconditionally rejected** even if future registration hashes are filled: the registered command manifest, real adapter and enforcement are absent. Synthetic mode is not an authorization boundary: it is for fake children only. Do not mount this candidate into subjects or run calibration/scoring. The embedding controller must authenticate itself, protect its process and bind one socket per isolated parent; possession of the socket is the authorization. The socket and its directory must not be shared with workers or sibling parents. It is mode 0600; fixed UID mapping and mounted-socket access must be established by the controller. Never expose host audit paths, this library or host config to subjects.

## Fixed supervisor shell CLI

Install `gemma-broker` at an immutable controller-selected location; mount only that CLI and the parent-specific socket as `/run/study/gemma-broker.sock`. The socket path is a source constant, not an environment variable or argument. UTF-8 JSON is printed as one line. Syntax:

```
gemma-broker call REQUEST_ID [WORKER_SESSION] < public-work-request.txt
gemma-broker get REQUEST_ID
gemma-broker cancel REQUEST_ID
```

Work is stdin, 1–16384 UTF-8 bytes, including newline if supplied. IDs use `[A-Za-z0-9_-]{1,80}`. The CLI does not accept extra flags. Exit 0 means a valid protocol response, **not** successful work; inspect `status`. Exit 1 means broker/transport or protocol error; exit 2 is invalid CLI input. `call` admits asynchronously and returns `running`; poll `get`. An identical call ID/body returns its current or original result; changed body or session gives `id_conflict`. `busy` is not admitted and its ID may be reused. Unknown ID gives `unknown_request`. `cancel` requests TERM then KILL for the active process group, asynchronously; poll for `cancelled`. Repeating cancel/get after completion returns the result. Successful output is `{request_id, session, status:"handoff", public_response, references}`. References are opaque controller-generated same-workspace `change`/`check` IDs, not paths or content. Controller must supply a public resolution mechanism; none is implemented here. Errors are `invalid_request`, `unknown_request`, `id_conflict`, `unknown_session`, `busy`, `stopped` (with reason), `invalid_cli`, `broker_unavailable`. Terminal statuses are `handoff`, `worker_error`, `cancelled`, `deadline`, `interrupted`, `output_limit`; no raw exception/stderr is returned. No worker final is a parent final.

Socket framing is one JSON object plus LF, at most 65536 bytes including LF, one request per connection. Duplicate keys, extra fields, invalid JSON, multiple frames and invalid IDs are rejected. At most 16 concurrent socket handlers, each with a 2-second read timeout; overload can close a connection. CLI read timeout is 3 seconds. JSON response including LF is also limited to 65536 bytes; oversized response becomes `worker_error`. Up to 1 MiB combined worker stdout/stderr is captured; excess cancels the worker. The runner preserves partial output but does not accept it as a handoff. The worker stdout contract is precisely one JSON object with only `public_response` (UTF-8 string, max 16384 bytes); adapter must explicitly classify this as public. stderr and all other events are host-only. Generic text is not automatically safe: controller must enforce isolation and public classification. No hard guarantee against malicious worker voluntarily emitting secrets it can access; preventing access is mandatory.

## Host config and controller API

`Broker(config, registration, freeze, global_stop, handoff_refs)`. Config is host-created, never received from the socket; do not put credentials in it, argv, child stdout/stderr, callbacks or usage events. Required config: `mode`, the registered route fields `requested_id`, `resolved_id`, `provider`, `provider_tag`, `quantization`, booleans `allow_fallbacks`, `zdr_required`, `run_id`, `parent_session_id`, `baseline_id`, `deadline_monotonic`, `argv`, `file_hashes`, `workspace`, `audit_dir`, `socket_path`. All IDs follow the CLI pattern. The deadline is an absolute `time.monotonic()` value computed by the controller at initial parent dispatch on the same host/boot and never extended; a process restart cannot reuse it without controller recovery. Command argv is fixed, host-only, absolute executable and fixed argument tokens; file_hashes is an absolute-path-to-SHA-256 map including the executable and all executable/config files used by the template (the broker cannot discover transitive dependencies). Hashes are checked on construction and before each spawn, but TOCTOU requires immutable mounts. `workspace`, `audit_dir` and `socket_path` are host absolute paths, audit outside the workspace; use fresh private directories. Config is deep-copied, a hash and identities are audited; config itself must be archived separately by the controller. Files are not created in `inputs/`.

Exact route is Gemma `google/gemma-4-31b-it`, resolved `google/gemma-4-31b-it-20260402`, Crusoe `crusoe/bf16`, bf16, ZDR required, fallback false; validate against both registration and the hard-coded exact tuple/allowlist. Registration's `settings_sha256`, `full_harness_qualification_sha256` and applied provider pin are currently null/false. Registered mode also refuses unconditionally; there is no provision to present a self-selected synthetic hash as registered authority. The synthetic fake executable is not evidence of model route or isolation. Host controller must freeze and qualify a complete manifest covering command, adapter, prompt bundle, settings, mounts, public contract, FAQ, scopes, resources, tool permissions and gateway; the current code does not supply or enforce those. OpenCode worker session persistence through a command is not implemented. Current policy: omitted session makes an opaque fresh ID; a session is eligible for continuation only after a successful handoff and belongs to this in-memory parent. Retries with a new request ID are explicit supervisor decisions; no auto retries or model fallback. Process loss loses idempotency/session state: controller must treat it as interruption, never restart broker into the same live parent and duplicate work.

Each child receives only bounded stdin JSON: work, worker_session_id, parent_session_id, run_id, baseline_id. Parent deadline and public task metadata are not supplied by this stub; real integration must deliver frozen public metadata via immutable host-controlled files/adaptor without granting socket-supplied path selection. Child cwd and PWD are workspace, env is minimal PATH/PWD/LANG, no inherited environment credentials. Host-only controller collects all other prompt, tool, response, retry, check, revision, resolution and native/provider events via `record_view(actor, kind, payload, request_id=None)`. Worker views require a known request ID. JSON payload max 1 MiB per event; actor is `supervisor` or `worker`; kind is `prompt`, `event`, `native_usage`, `provider_usage`, `retry`, `check`, `revision`, `resolution`. These are separate raw views, not reconciled, verified, charged or deduplicated. Controller must provide timestamps and correlation, ensure no secret values enter any audit, archive partial streams and paid failures, preserve native and raw provider counters separately, and implement durable event capture/normalization/missingness. This API is an ingestion hook, not evidence that collection actually occurs. No retries are hidden. Audit writes JSONL with host UTC/monotonic timestamps, admission/ancestry/digest, chunks, error types, stop/freeze outcome, controller views; mode 0600 exclusive creation, directory private, no fsync/crash recovery. Logging failure has not been hardened: real controller must fail closed and preserve missingness if storage fails.

## Stop, final and snapshot semantics

A lock serializes stop/admission/spawn. Monotonic timer closes admission, kills the worker process group and waits for runner cleanup. `stop(reason)` accepts `deadline`, `parent_final`, `user_stop`, `budget_exhausted`, `infrastructure_failure`, `protocol_violation`. First reason wins; stop is idempotent. `budget_exhausted` calls host `global_stop(reason)` exactly once to signal global admission stop; this callback must implement global synchronization across parents. It is not implemented in the input inference proxy. Failure is audited; controller must independently fail global admission closed. `parent_event(event)` accepts only `type=step_finish`, `part.reason=stop` with top-level or part `sessionID` matching parent, and no conflicting session ID. This is the candidate OpenCode JSON shape and must be verified against the pinned real stream. Text and child events are not endpoints. A trusted controller must pass all events, including race-sensitive ones, from the real source; parent completion is never inferred from worker JSON. Call `stop` on every other external stop.

After broker worker cleanup, `freeze(reason)` is called **once**, outside the broker lock and before stop returns. Controller MUST quiesce supervisor, all tool children and services, kill container/cgroup escapees, revoke workspace writes, then atomically snapshot/freeze and record success before returning. It must handle deadline/final races across controller components; if any step cannot be proven, raise and mark `freeze_failed`, never label an endpoint frozen. The callback must not reenter `stop` or hang; stop waits without timeout. This hook is the sole late-write prevention boundary; killing a Unix process group is insufficient for detached/session-escaped children or external writers. On normal handoff a process group is also killed; a new session must use an adapter capable of actual continuation. External supervisor cancellation of only the CLI PID does not cancel the worker: explicitly call `cancel`, or let the trusted controller stop the parent. Connection loss does not cancel an admitted request. Freeze failure keeps admissions stopped. `close()` stops if necessary and joins timer; controller must shut down the socket server before close. A fresh socket path is required; server never unlinks it.

## Usage schema and review limitations

No usage helper or schema is forked. `inputs/schemas/provider-usage-record.schema.json` and its normalizer remain revision-2 GLM/Relace only, not a Gemma mapping or all-model qualification. The recorded U4 later-warning-loss and U5 pathological exception types remain unresolved in those immutable inputs; do not claim their stated warning/exception guarantees for arbitrary inputs. Never add OpenCode native and provider counters as separate charges; raw events are distinct views and absent usage stays missing, not zero. A real integration must define final-versus-partial capture, response identity, retries/ancestry and duplicate/conflict resolution, qualified mapping and evidence, actual route resolution and billing reconciliation. Provider exhaustion must stop globally, not switch models.
