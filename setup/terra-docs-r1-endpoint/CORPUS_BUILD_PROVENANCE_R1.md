## Extraction and equivalence

`diagnostics/select.py` copies selected **whole named heading sections**, or whole short source pages, with a generated two-heading wrapper. Original lines are not rewritten. Upstream MDX, markup, relative links and site macros are retained, not rendered; complete section selection does not imply full documentation coverage. Installed `.d.ts` files are fenced, verbatim. `sqlite-extract.mjs` and `w3c-extract.mjs` extract identified complete HTML sections/entries and convert with the installed Turndown; HTML offsets are UTF-16 indices. Rendered SVG syntax diagrams, website style/behavior and out-of-section links are not reproduced; consult original URLs when needed. Attribution/rights and raw acquisition metadata remain outside `docs-files/` and the index.

First technical content was written to `docs-files/`; `diagnostics/build_archives.py` then created local Context-compatible SQLite/FTS5 archives only from those files, without network fetch or model. It is a **custom schema-compatible byte-preserving writer**, not Context's markdown importer: the importer drops headings/ToC-like sections and rewrites some MDX. The writer stores each document as contiguous chunks and indexes with Context's `porter unicode61` FTS5 schema. `diagnostics/equivalence.py` validates all 22 SQLite databases, FTS document IDs, metadata, and exact reconstruction of all 118 files from all 167 indexed chunks, with bidirectional set equality. `diagnostics/equivalence-result.json` includes every file and chunk ID. This proves byte parity of stored technical sections, not that lexical search returns every portion of a long file in one query; Context applies ranking and a token budget. All indexed files are the proposed local allowlist, not qualified or frozen approvals.
